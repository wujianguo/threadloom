# Domain docs

Use a single-context layout: `GLOSSARY.md` and `docs/adr/` at the repo root.

Before working on domain concepts, read the root glossary if it exists and relevant ADRs from `docs/adr/`. These files are created when terms or decisions are resolved; their absence requires no setup work.

Use terms as defined in the glossary in issues, proposals, hypotheses, and tests. If a needed term is missing, reconsider it or record the gap for `/domain-modeling`.

Surface any conflict with an existing ADR explicitly.
